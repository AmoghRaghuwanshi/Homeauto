# Cloud identity and authorization

Existing local authentication and offline access remain separate. Neon Auth was evaluated against the current local session model; this implementation retains its scrypt verification contract and adds PostgreSQL-backed online users, sessions, membership and audit records. No provider switch or password migration is hidden in the UI. Native voice remains on the home hub; no microphone audio is uploaded to Neon.

Cloud login has no guest/preview administrator. Owner/resident/viewer memberships are checked on every authenticated request. Viewers can read their household and manage their own preferences/alert receipts; only owner/resident can request approved lights. Owner-only diagnostics and all operator enrollment/recovery are protected. Metadata/RFID management stays on the local hub in this release. Remote door control cannot be enabled by a browser or cloud setting.

Secure host-only HttpOnly SameSite=Strict cookies contain random tokens; PostgreSQL stores only hashes. Sessions have an 8h absolute bound and 30min activity idle bound; polling does not renew them. Reauthentication/household switch rotates the token while retaining the original absolute expiry. PostgreSQL serializes rotation/logout on the user row and retains revoked token lineage: an in-flight logout using an old token revokes its derived sessions, and a logged-out token cannot rotate. Password verification is checked against the current stored hash again at issuance/reauthentication. Logout, password recovery, disabled memberships/users and quarantine revoke sessions. Browser generation guards reject old responses after rotation/logout/switch. Same-origin CSRF tokens protect mutations, in addition to exact Host/Origin checks, JSON/body bounds and parameterized SQL. No wildcard CORS is enabled.

Shared database throttling covers reads/writes, login IP/username, reauth, gateway requests and per-device command requests. Login limits are 20/IP and 5/IP+username per 15min; hashing is concurrency bounded per instance. Normal user read/write budgets are 180/90 per minute, gateway 120/minute and light requests 20/device/minute. Infrastructure-level abuse controls and native multi-instance load still need staging validation. Responses/logs avoid raw SQL, URLs, passwords, tokens, key files and audio.

## Operator recovery and administration

`online-operator.js` requires `--apply`, explicit administrative approval, direct non-pooler URL and matching expected database name before connecting. Verify the branch/project independently. Except initial migration, mutations require the schema-owner operator. Runtime role grants/owner rejection are described in [schema](NEON_SCHEMA.md).

Supported commands: `household NAME`, `create-user HOUSEHOLD_UUID USERNAME DISPLAY_NAME ROLE`, `membership HOUSEHOLD_UUID USERNAME ROLE`, `reset-password USERNAME`, `disable-user USERNAME`, `enroll-gateway`, `rotate-gateway-key`, `revoke-key`, `revoke-gateway`, `quarantine HOUSEHOLD_UUID` and `maintain HOUSEHOLD_UUID`, each followed by `--apply`. Password creation/recovery reads `HOMEAUTO_CLOUD_OPERATOR_PASSWORD` from the private process environment, not a positional command argument. Verify recovery authority out of band; there is no public password-reset endpoint or guessed email workflow. Membership roles are owner/resident/viewer/disabled. Password reset/user disable revokes all that user's cloud sessions; membership changes revoke that home session. Never remove a home's final trusted owner without an independently secured recovery operator.

Gateway credentials are separate, expiring and scoped. The schema/runtime cannot authenticate a browser with a gateway token. Requests require HTTPS; certificate verification cannot be disabled by URL SSL parameters. Local remote-light enablement also requires authenticated MQTTs configuration and explicit secure-gateway approval, which is a policy gate, not automatic proof that AUD-001/002/003 are resolved.

Software tests cover roles/RLS/CSRF/replay/revocation/races, not a penetration-test certificate. No cloud keys, accounts, deployments or physical hardware were changed.
